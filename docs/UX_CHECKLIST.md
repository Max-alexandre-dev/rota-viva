# Checklist de aceitação de UX — Rota Viva

## Clareza
- [ ] Em 5 segundos, dá para identificar a necessidade prioritária?
- [ ] Cada indicador tem nome, unidade e origem do dado?
- [ ] Há uma ação primária claramente identificada por tela?
- [ ] Distinção visível entre `sugerida`, `aprovada`, `em trânsito`, `recebida`?
- [ ] Diferença entre déficit físico e déficit planejado está clara onde aparece?

## Operação
- [ ] Nenhum saldo físico muda antes do evento de retirada/recebimento correto?
- [ ] Propostas mostram o motivo e limites de estoque?
- [ ] Estado crítico indica qual decisão humana falta?
- [ ] Não há confirmação de entrega duplicada?
- [ ] A tela não indica que uma rota é segura sem validação externa?

## Experiência
- [ ] Teclado, foco visível, label de inputs e contraste funcional?
- [ ] Sem rolagem horizontal em 390px?
- [ ] Estados vazios e erros permitem que o usuário saiba o que fazer?
- [ ] Avisos de conexão distinguem dado local de dado confirmado no servidor?
- [ ] Ações importantes pedem confirmação e exibem resultado?
- [ ] Não há números, mapas ou percentuais inventados apresentados como realidade?

## Competição
- [ ] As três ações centrais podem ser demonstradas em até 3 minutos?
- [ ] A demo e o repositório têm URLs públicas e documentação?
- [ ] Todos os dados pessoais da demo são sintéticos?
- [ ] Ações descritas como offline foram efetivamente testadas offline?
